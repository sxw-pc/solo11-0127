# 面单印发核台

物流站点把本地面单软件的打印作业、主管重印授权和承运回执采入同一 SQLite 证据账。印制判断纸号、模板与回执；重印裁决原份作废和新份生效；交接核对面单、重量、承运人，并独立结算整批交接。原始桌面导出字节及 SHA-256 持久化，JSON 报告列来源、实体、问题和每次业务决定。

四个入口分别是 `print-import`、`reprint-request`、`handoff-evaluate` 和 `handoff-settle`，均接收 `--db ledger.db export.json`。导出 JSON 顶层含 `version` 和 `rows`。`demo` 会在临时目录生成完整正常链路；测试还覆盖纸号冲突、缺打印回执、授权过期、重量不符及部分失败结算。

## 物理输出证据

队列导出中的 `printed=true` 只是导出软件的声称。传入 `--keys`（或设置 `LABELDISPATCH_KEYS`）即进入认证模式，份次必须由以下任一可信物理输出证明才有效：

* **设备认证合同**：`printer-receipt` 采入印机签章消息，绑定打印机、`copy_id`、纸号、模板、设备递增序号、打印结果与该队列导出的 SHA-256。HMAC 密钥由运行时受控文件提供（`{"printers":{"P1":{"active":"k2","keys":{"k1":"...","k2":"..."}}}}`）；仓库与测试只用虚构密钥，密钥与签章不写入报告，仅记录指纹与签章摘要。
* **现场双人见证合同**：`physical-witness` 记录设备离线时两名独立操作员对同一纸号/份次的实物扫描；只一人、同人重复或纸号不一致均不放行。

签章不符、纸号/模板/导出摘要不匹配、设备号与预留不符、序号回退、同序号异文、纸号已用于另一份次，以及换钥后旧密钥签署的新消息，都不能声称打印成功，也不会消耗纸张。保留旧密钥版本可继续验证历史回执，重放旧回执不会重复计入库存。设备故障时原队列、预留与回执全部保留，后续 `printer-receipt`/`physical-witness` 可补齐；已交接份次不会被后到证据静默改写。

打印资源是独立的排程决定：`printer-plan` 读取桌面设备与纸库存快照，为份次分配支持模板且有纸、有空闲容量的打印机。`printer-cancel` 必须提供无纸张输出的操作员证据才释放预留；已消耗的纸张不会因重试回到库存。印制及授权补印会读取排程结果，资源不足时等待；认证模式下重印获批后新份仍须物理输出证据。库存快照是采入原样，消耗单独记账，报告由两者推导可用量。

承运方接收后仍可提出实物争议：`carrier-claim` 核对实际看到的面单份次，证实不符时把包裹置于召回中、把已结算批次重开；`recall-resolve` 依实物扫描证据结束追索。争议被驳回时原交接结论不变，重放旧结算导出也不能重新封账。无有效原份、占用中的新份 ID 或已用纸号不能获批重印；召回中的包裹不能再次交接。相关来源、预留、索赔与召回实体均写入台账；演示只用本地虚构文件。

`report` 输出 `evidence` 段：有效面单（含证据等级 `device`/`witness`/`legacy` 与队列导出来源）、待核原因、作废份次、回执来源摘要、纸库存与消耗。未配置密钥的 `demo` 保持原有队列布尔行为，但所有份次明确标为 `legacy` 证据等级。

运行：`python -m pip install . --no-deps --no-build-isolation`，`python -m labeldispatch demo`，`python -m labeldispatch --help`，`python -m pytest -q`。所有演示和测试使用虚构本地文件，不访问网络。
